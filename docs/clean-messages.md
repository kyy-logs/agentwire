# 聊天正文无协议编号：运行与验收

此文描述 AgentWire v0.1.0（clean-v1）实现。本版能力与已完成验收见 [本版验收与边界](CLEAN-MESSAGES-ACCEPTANCE.md)。仓库和分发包不携带私人会话日志。

## 日常使用

安装与连接方式沿用 INSTALL.md。选好已有聊天后，在 Codex 说“让 Claude 只读审查当前修改”，或在 Claude 说“让 Codex 分析这个问题”。两端 Skill 调用本地客户端，用户不必手工执行 ask，不必复制或记住任务编号。

聊天中的任务包含来源、任务与简短权限边界，回复包含来源、结果和必要状态。Bus 内部仍保存完整编号，Codex 通过原生 clientUserMessageId，Claude 通过原生 peer uuid 关联原生回合；编号不作为任务提示词发送。原生程序自己的来源包装由原生程序决定。

发送结果不是业务成功证明。“本回合已结束”只说明收集到了该回合的终态，仍需按需求验证测试和审查结果。回复本身不触发自动回声；下一轮必须在用户授权计划内显式 followup。

## 排障

| 状态 | 含义与操作 |
| --- | --- |
| submitted/queued | 进入原生队列或已接收；等待精确回合和结束事件，不重复发送 |
| needs_check / 未知投递 | 用 status/doctor/check 核对原消息；不能新建编号重发 |
| native_binding_conflict | 身份对应多回合或回合被多任务认领；暂停核对，不能取最近答案 |
| background_pending / continuation | 尚不能认定任务结束；查看原窗口，不自动声称成功 |
| result timeout | 停止正常等待；不代表原生任务已取消，不自动重投 |
| native read limit/schema error | 原生格式或查询限制未满足，保留消息并报告，不能按正文猜测 |

本地状态可显示传输身份、原生执行身份、结果位置及校验值；这些诊断不再自动发送到聊天。自动任务不插入五分钟等待提醒；手动模式必要的回信提醒保留。

## 兼容与撤销

旧 schema1/legacy 记录、已完成连接和手动模式保留。新自动根任务为 schema2/clean-v1，其子消息继承版本和精确目标。不得转换或重发旧在途消息。

回滚前正常关闭 Bus，保留运行时、配置和状态备份。旧 r2 不认识 schema2；不能对同一 clean 在途状态启动旧运行时，应先归档/暂停，再使用隔离 legacy 状态恢复。不要删除消息历史来消除未知投递，也不要结束原生 Agent 代替取消任务。

## 验收边界

离线测试包括：同正文不同身份、普通输入/sidechain不匹配、停止先于映射、隐私、结果/回复重复、超时不重投、跨进程写后崩溃、手动回复优先、关闭期间结果保留和安装卸载兼容。

原窗口已验证两个方向各两轮、两条同正文独立任务之间的实际人工聊天、Bus受管重启、Claude正常退出后恢复同会话，以及恢复后的Read工具调用与自动回传。无写代码的Java/Spring Boot业务闭环、本版Codex自身正常退出恢复、原生错误/中断的真实端到端场景仍未验收。离线回归、原窗口真实交互和业务需求验收分别记录。

## 工具调用后的采集

Claude的tool_result仍可能携带同一promptId，不能一律当作新人工输入。本版只沿已登记任务的parentUuid祖先链接纳匹配未完成tool_use_id、同promptId且非peer来源的工具结果；普通输入、陌生工具结果或另一prompt仍是边界。实际Read调用后的结果回传已通过。

信息回复的送达由精确原生输入身份确认，与接收方之后输出几条答案无关；任务输出出现歧义时仍保守暂停，不取最近文本。

接收方需要结束当前回合才能消费队列时，应提交后结束回合，不在自己的工具调用中阻塞等待自己处理回复。
