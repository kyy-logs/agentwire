# 配对输入 Hook 超时排障

## 已确认的故障链

Claude Code 报 `UserPromptSubmit ... timed out after 5s — output discarded` 时，
本次 Hook 输出不会进入模型上下文。后台可能已经暂存配对请求，这不表示聊天收到了凭据，
也不表示已签发连接码。本次实际记录中，原生人工输入到请求暂存约 6.8 秒，超过原先的
5 秒上限；普通非配对输入的三次独立进程探测约 0.27–0.28 秒。尚未证明超时发生在内部
哪个步骤，不能把它直接归因于 Node 启动、磁盘、杀毒软件或网络。

`AGENTWIRE_PAIR_REQUEST=<凭据>` 来自 Hook 的 `additionalContext`，是当前回合的
上下文文本，**不是环境变量**。`echo`、`printenv`、PowerShell 环境查询得到空值不能
证明上下文没有凭据。`doctor` 的 `nativeTrust: unverified` 也不表示已证明未信任；
它只表示只读文件检查不能确认原生程序实际加载或信任状态。

## 修复范围

- Claude `UserPromptSubmit` 默认超时由 5 秒改为 15 秒；Codex 输入 Hook 和双方结束
  Hook 保持 5 秒。延长预算降低此次误超时风险，不承诺以后不会超时。
- 两端 Skill 与 Hook 注入说明明确从当前原生上下文读取凭据，不从环境、最近记录、
  用户粘贴或另一聊天借用凭据。没有凭据时停止发码，不切换旧连接代替本次请求。
- 安装器按之前登记的精确 Hook 定义原位升级，保留无关 Hook 和权限。外部改过的同命令
  定义暂停审阅；升级与回滚保存前任所有权，以支持再次升级和卸载。部分应用、部分回滚
  的卸载顺序只依据实际剩余工作，避免错误的所有权循环。

## 用户如何复测

更新运行时、Skill 和已有产品 Hook 后，在**原目标 Claude 聊天**重新发送纯文本
`生成连接码`。如果仍显示 5 秒，检查该聊天原生 `/hooks` 是否仍加载旧定义，按原生方式
刷新或恢复会话；不调整权限、不改填会话 ID。旧请求过期后不能复用，后台暂存记录也
不能替代新的人工输入。

发码必须以这次 `pair issue --intent` 的程序结果为依据；发码成功、兑换成功、任务往返
分别核验。离线回归通过和磁盘安装一致都不能替代真实聊天的本轮发码结果。

## 本次验证（2026-11-18）

- `npm test`：331 项通过，失败、取消、跳过均为 0，退出码 0。
- 配置专项 17 项通过，覆盖 5→15 秒原位升级、外部改动拒绝、保留无关设置、升级回滚后
  再次升级、完整卸载及部分应用／部分回滚后的卸载。
- 两端 Skill 的隔离命令选择检查覆盖上下文凭据存在、仅有旧环境值、超时加旧连接三种
  情形；这是说明约束检查，不是实际模型发码证明。
- 当前安装更新 4 个自有运行时文件、2 个 Skill，以及 Claude 已有产品输入 Hook 的
  timeout 字段。所有其他 settings 内容、Codex Hook、现有配对路由和原消息历史经哈希
  或结构比较保持不变；Bus 正常退出后重启，安装后四类待处理计数均为 0。
- 修复后的原报错 Claude 聊天已由真实人工输入触发新一轮请求；精确输入仅 1 条、请求
  已核验，并存在包含对应新码的正式成功工具结果。本次输入到请求暂存约 0.51 秒；
  这证明此次发码通过，不证明所有冷启动时延问题已消除。
- 用户最初通过问答卡片提交代码时，当前 Codex 没有兑换句式的原生请求，因而未借用历史
  凭据。后续真实输入首次被已有活动连接拦截；补齐安全换绑后，又一次新的真实输入正式
  兑换成功，新聊天身份已配对，见[安全换绑验收](PAIRING-REPLACEMENT.md)。任务往返仍待验证。

## 后续观察：上下文已进入请求但模型仍查询环境

同日 Claude 侧一次反向兑换未调用 `pair redeem`，只执行 Bash 环境查询并据空值报告
凭据缺失。精确人工输入到请求暂存约 0.37 秒，已配置 15 秒；原生 attachment 与
api-request-blob 同时包含本次精确票据、新版“不是进程环境变量”说明和兑换指令。
因此不能把该次失败归因于 Hook 未运行或凭据未进入 Claude 构造的模型请求。
这里没有捕获中间代理转发后的最终请求，不能进一步断言代理无改写，也不能仅据此归因
于某个模型品牌。实际可确认的是：兑换工具未执行，原配对未变，代码仍未使用。

这也限定了本修复的结论：成功的一次原生发码、兑换不保证模型以后始终按上下文取票据。
增加超时和文字说明不能提供确定的工具执行保证。后续若要求不依赖模型遵循指令，需要
单独设计由程序校验精确原生输入并执行配对动作的入口，同时保留原生审批和拒绝边界。
