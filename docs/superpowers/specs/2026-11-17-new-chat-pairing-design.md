# AgentWire：安装一次，新聊天直接配对

日期：2026-11-17。状态：设计补充，待书面审阅；未实现、未激活。

本文件补充 `2026-11-17-pairing-codes-design.md`。原设计的数据结构、有效期、单活动连接、原生来源门槛、事务恢复和旧任务保护保持有效；本文件明确新聊天准入、用户入口和安装要求。实现计划需在本补充审阅后同步调整，P0 未通过仍不得实施持久配对模块。

## 1. 目标与范围

用户在已安装 AgentWire 的同一个 Windows 用户环境中新开 Claude Code 和 Codex 聊天，无需提前登记窗口，无需知道会话 ID，也无需切换到相同目录。在目标聊天输入“生成连接码”，在另一聊天输入“连接 Claude，连接码 XXXX-XXXX”，即可准确配对。

“安装一次”指双方 CLI/应用可用、用户级 Hook 和 Skill 均已安装、原生信任已完成，且新聊天加载了这些配置。全新电脑、另一个 Windows 用户、WSL/容器/远程主机不自动共享安装或配对状态，不在本期范围内。配置被外部工具删除也不算安装仍然完整。

用户已明确希望新聊天可用；本设计采用的首版取舍是固定配对句式、仅一组活动连接、两个原生主聊天、同机协作，沿用先前约束。日常任务仍可自然语言委派。

## 2. 方案取舍

| 方案 | 优点 | 限制 |
|---|---|---|
| 用户级 Hook 捕获明确配对输入，Skill 调用程序并展示结果（推荐） | 复用现有安装、原生身份和配对事务；新聊天不需登记 | 必须验证两端 Hook、来源证据及精确凭据传递；Skill 展示不保证模型永远遵循 |
| 仅靠 Skill 读取或填写会话 ID | 改动较少 | 模型填写的身份不构成来源证明，不能满足准确配对要求 |
| 扫描所有窗口，由标题或目录自动挑选 | 看似省一步复制 | 同标题、同目录、新建与恢复容易混淆；仅作为旧候选列表入口，不能自动授权 |

推荐方案不增加新的后台守护程序、消息系统、SQLite 或第三方 API。它复用现有安装和 Bus，新增配对控制入口。

## 3. 用户操作与程序职责

### 3.1 首次配对

1. 在任意新 Claude 主聊天输入 `生成连接码`。也接受原设计的 `给这个聊天生成连接码`；允许首尾空白和末尾换行，不解析引用、代码块、附加正文或模糊同义表达。
2. 原生 UserPromptSubmit Hook 获取当前输入身份；程序核验真实人工来源，保存只属于这次输入的短期操作凭据，并通过该回合的原生上下文交给 Skill。凭据不按“最近一条”查找。
3. Skill 使用精确凭据调用 `labus pair issue --intent <凭据>`。程序生成连接码并返回实际结果；Skill 展示该结果。模型不生成代码、不提供路由身份。
4. 用户看到：`本聊天连接码：7K4M-9Q2R；1小时内有效，仅可使用一次`，并附聊天与目录信息供人工核对。此时仅发码，尚未连接。
5. 在目标 Codex 主聊天输入 `连接 Claude，连接码 7K4M-9Q2R`。反向流程为 Codex 发码、Claude 输入 `连接 Codex，连接码 …`。
6. 兑换侧同样通过原生输入产生精确凭据；CLI 校验凭据中已确定的代码和身份，原子占用并提交绑定。成功提示 `已配对；实际任务往返尚未验证`。不自动派发算术题。

第一版不承诺任意自然语言必然触发 Skill。用户级 Skill 描述必须包含上述固定句式；提供显式 `/labus` 入口和帮助，按同一原生来源规则执行，不能绕过验证。若原生显式 Skill 输入事件与普通输入不同，须独立验证后才启用该后备入口。

模型不调用 CLI 或不展示结果属于可用性失败，不能产生虚假的成功记录。界面不得把模型随机生成的 UUID 视为有效连接码；只有本地程序的持久发码记录和成功兑换结果有效。程序验证失败时返回具体原因，不能要求模型猜会话。

### 3.2 新聊天如何被认识

新聊天不需要出现在预登记的 session allowlist 中。用户级 Hook 可在任何受支持主聊天运行，但只在识别明确配对句式后进入来源验证；普通输入不新增落盘。输入文本只表明请求类型，不能单独证明授权。

配对控制处理必须位于 `hook-router.ts` 当前“没有路由就返回”的分支之前。已配对任务的生命周期采集仍按精确旧路由处理，禁止因为放开发码准入而扩大结果采集范围。

原生 provider + sessionId 是持久身份；原生输入/回合 ID 是本次操作身份。cwd、标题供展示，PID 仅用于端点查找。程序结合可核验的原生记录拒绝 peer/channel、工具输出、子 Agent 和来源不确定的输入。它们即使包含完全相同的“生成连接码”，也不产生有效 PairIntent。

## 4. 分类行为

| 情况 | 用户操作 | 程序行为 |
|---|---|---|
| 两个全新聊天，尚无活动连接 | 在目标发码，在发起侧兑换 | 无需预登记，按两端原生身份绑定 |
| Claude 在不同目录 | 同上 | 目录不同不影响定位；展示双方目录，文件访问与权限另行判断 |
| 同标题、同目录有多个聊天 | 在真正目标聊天发码 | 只绑定发码者的原生 Session ID，不选“最近活跃” |
| 新开 Claude，旧连接仍存在 | 可发码；兑换时先处理旧连接 | 返回 active_connection_exists，不自动换绑 |
| 旧连接有在途或状态不确定任务 | 先核对旧任务 | 普通切换保持阻止；显式归档不代表取消原生工作 |
| 恢复同一个原生聊天，PID 改变 | 已配对时直接检查状态 | 保留身份，重新发现端点；不因 PID 改变强制发码 |
| 新 Codex 聊天 | 新聊天兑换连接码 | 不继承旧聊天连接，不把旧回复重定向给它 |
| 同一原生会话出现两个活跃端点 | 保留一个明确端点后再操作 | 端点不唯一时拒绝激活或发送，不任选其一 |
| 目标发码后退出或代码过期 | 恢复原会话；过期则重新发码 | 不自动换成另一个在线 Claude，不重放已消费代码 |
| Hook 缺失、未信任或版本不兼容 | 查看诊断并修复安装 | 报安装/能力缺口；不能声称已经识别或连接 |

## 5. 安装与故障提示

安装器写用户级、绝对路径的双方 Hook 和 Skill。启动目录不能决定是否加载 AgentWire；项目级设置、管理策略等仍可能改变有效配置，必须在实际加载的新聊天验证。首次安装和变更后的原生信任遵守应用要求，不承诺自动代替。

复用现有 doctor 命令，分别检查磁盘配置、脚本路径、Skill 文件、版本、原生信任可见性、当前聊天实际观察证据。必须区分“文件已写入”和“当前聊天已执行”，没有后者时标为未验证。原生进程要求重载或重新打开时给出具体提示，不能反复建议重启代替诊断。

Hook 被删除后，缺失的 Hook 本身不能向聊天报错。安装后诊断、用户显式调用 Skill/CLI 时应提示缺失；若 Hook 和 Skill 都未加载，普通聊天无 AgentWire 反馈是可预期的故障，不能承诺静默自愈或自动覆盖被外部修改的配置。

推荐错误提示：`未识别到本次原生配对输入，未创建连接。请检查 AgentWire Hook 是否在当前聊天加载。`、`这个聊天已有其他连接，请先处理旧连接。`、`目标聊天当前无法唯一定位，请恢复发码的原聊天。`

## 6. 改动位置与验收

沿用原设计的 `src/pairing/{model,capture,store,service,cli}.ts`。补充修改 `src/installation/hook-router.ts`（未配对控制入口）、`configuration.ts/setup.ts`（用户级安装及只读诊断）、双方 `assets/skills/*/labus/SKILL.md`（固定入口和实际结果展示）及相关测试。根据现有命令分派落点复用 doctor，不新增臆造的 doctor.ts 文件。

必须覆盖：

1. 原生 P0：两端未配对聊天的固定发码/兑换输入、人工来源、精确凭据返回；失败则保持后续门槛。
2. 安装后新建、未列入任何 session allowlist 的两个聊天，可完成一次发码与兑换；安装配置不再为单个聊天重写。
3. 跨目录、同目录同标题多聊天、恢复后 PID 变化均指向准确原生身份；同会话多端点拒绝歧义。
4. peer 相同口令、引用/代码块、工具输出、子 Agent、普通输入、重复与过期兑换均不误配；普通聊天无新增持久正文。
5. Hook 缺失、未信任、配置覆盖、Skill 未触发时不出现虚假成功；错误与未验证状态有准确诊断。
6. 新配对不自动发任务，旧版连接与生命周期路由不变，旧任务回复不串线；随后独立验证任务往返与 followup。

现阶段已观察的单个 Claude 探针阳性和临时脚本 4/4 自检，仅用于继续 P0，不证明本设计已实现，也不证明任意新聊天可用。

## 7. 源码依据

- `src/installation/hook-router.ts:routeHook` 当前先查 routes、无匹配返回；这是新聊天控制请求必须前置的具体原因。
- `src/installation/source.ts:readCallerSource` 当前可接收 Skill 提供的 Claude sessionId；新配对不能仅依赖此参数。
- `assets/skills/claude/labus/SKILL.md` 当前仅有 discover/select 与任务委派；尚无发码入口。
- 原配对设计及实施计划固定原生来源、单活动连接、原子恢复和临时配置授权边界，本补充不取消这些要求。
