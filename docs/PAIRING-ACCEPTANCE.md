## 能力与恢复

Codex 的本地候选索引只能确认已知身份，端点状态保持 unknown；Claude 需唯一活端点。
两者都不是送达证明。doctor 区分磁盘配置/Skill/运行时存在与原生实际加载，
无法核实的信任、版本和当前聊天观察明确标为 unverified，不静默修复外部配置。

占用代码后始终通过同一激活事务恢复，即使代码/首次操作期限已过。任何冲突停在
needs_check，不另分配连接 ID。配对后旧终态账本可按保留期清理，完整连接身份仍保留；
未完成账本永不因清理而解锁发送。原生工作取消、进程重启后的业务完成不能由 Stop 推定。

已完成配对的路由缺失或冲突时暂停核对，不猜测补写；历史已断开的连接不会因重试重新激活。
精确查找仍有原生索引字节窗口和目录扫描上限；无法完整确认时拒绝或报告不可用，
不能据此声称任意历史会话都可被发现。端点检测也使用精确查询，不受界面候选数量影响。

撤销使用现有安装器所有权与哈希校验，保留消息历史；外部修改冲突时暂停覆盖。
同一 Windows 用户下的防误配不提供恶意本机进程间隔离，也不保证断电时跨文件事务原子性。
