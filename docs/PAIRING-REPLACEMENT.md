# 用新连接码安全换绑

用户在当前聊天输入「连接 Claude，连接码 XXXX-XXXX」（反向为「连接 Codex，连接码 …」），
仍由本次原生 Hook 凭据进入 `pair redeem`。如果目标不同、旧连接空闲，程序自动断开旧连接
并连接新聊天，保留旧消息和结果，无需用户先发送断开命令。新配对不自动发送任务探针。

## 准入条件

1. 精确验证本轮人工输入、连接码的方向、有效期与唯一目标身份；Claude 目标须有实际端点，
   Codex 发现记录仍只证明身份，不能当作在线或任务往返成功。
2. 新双方可以都是新开的聊天，也可以只有一边更换；目录可以不同。本轮经原生身份验证的
   人工兑换请求表示切换本机唯一活动配对，无需先手动断开，也无需由旧聊天发起。旧连接
   须为正常 paired／旧版 ready，无错误标记；不会绕过新双方的精确身份核验。
3. 校验旧路由、绑定和历史，确认未完成任务、交付不确定、原生未结束工作、未处理生命周期
   文件均为零。任何一项失败，在消耗新码、关闭服务或改路由之前拒绝。

## 切换顺序与恢复

整个操作复用 `connection.lock` 与配对激活账本。先将旧记录哈希、断开后哈希和旧连接 ID
写入新激活的 `replacement` 字段，再设置现有 `connection-transition.json` 保护。
保护同时拦截正常入口和旧 Bus 的直接 IPC 投递；定时轮询遇到保护只暂停，不标为存储故障。

确认旧 Bus 正常关闭后，再读一次历史和绑定；若在途写入产生了新工作，保留保护并停止。
空闲时清空旧路由、标记旧连接 disconnected，将 detached 阶段提交账本，然后解除本操作
的保护，接续既有新连接激活流程。这个交接点的旧服务已退出、旧路由为空且旧记录断开，
随后才启动、绑定新服务并写新路由和活动指针。

中断后使用同一激活恢复，不再消耗代码或分配新连接 ID。旧记录和保护须与原事务精确一致，
冲突时保守暂停。旧端已断开后若新端离线，保留待恢复激活，不假称已连接，也不擅自重连
旧端。已验证的同一请求可幂等重入；一般用户不要从历史中寻找或粘贴内部凭据。

此流程不取消任务、不归档未决投递、不重放旧消息、不改原生权限，只支持一组活动配对。
历史配对的显式选择／预览／切换入口保持原规则。多文件写入依赖持久状态逐步恢复，
不承诺断电时的跨文件事务原子性。

## 双方全新窗口的使用流程

在新 Claude 聊天输入「生成连接码」，然后在新 Codex 聊天输入「连接 Claude，连接码 XXXX-XXXX」；
两端反向发码／兑换同样支持。旧配对正常且空闲时自动断开，消息和结果保留；
旧窗口不会被关闭，也不会收到新配对的消息。仍然只支持一组活动配对。
未完成任务、未知交付、未结束原生工作或存储异常会阻止切换，不自动取消或归档。
新码无效或新目标身份核验失败时不改变旧配对；切换中断沿原激活账本恢复，不重投任务。
