# 开发协作边界

首版验证了两个原会话的文本任务往返、只读工具结果回传；此前也验证过本工具修复与只读审查闭环，但没有对 Java/Spring Boot 仓库进行真实功能开发。使用前由用户指定开发仓库、任务和唯一写入方；会话 workspace 绑定不自动授予该仓库的修改权限。

推荐第一阶段 Codex 实现，Claude 只读审查。任务 send 说明目标、工作目录、验收命令、允许修改的范围；结果 reply 附实际测试命令、退出码和相关文件。审查意见通过 followup 引用上一条 reply；再次实现和测试后回复。不要将“Agent 说测试通过”作为实际测试输出的替代。

每根任务最多 6 次委派，30 分钟根期限、10 分钟结果等待上限；审批等待也消耗期限。超时进入 needs_check，先核对状态，不能认为原任务已取消并启动另一个写入者。stop 不会撤回原生队列或中断 Agent。过期后需要新任务时，先确认上个写入动作是否仍在执行。

Bus 不提供文件锁。两个 Agent 必须同时写时，各用独立 Git worktree；通过审查后的 patch/commit 交接，由用户指定的一方整合。合并、发布或提权继续遵守当前用户授权及各会话审批。

未来第三 Agent：实现 AgentAdapter 的 probe/submit/reconcile，在 main.ts 注册；同时扩展 model.ts 的 kind 类型及 cli.ts 的 bind kind 校验。复用现有路由、消息合同和预算；新增 kind 不等于已验证其原窗口投递。初版没有自动角色规划或跨根任务的全局执行预算。
